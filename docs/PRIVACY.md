# 개인정보 및 이미지 보관 운영 원칙

이 문서는 학교 부스 운영자가 지켜야 할 최소 개인정보 처리 원칙입니다. 실제 행사 안내문과 학교 내부 개인정보 지침이 더 엄격한 경우 해당 지침을 우선합니다.

## 처리되는 정보

| 정보 | 사용 목적 | 전달 대상 | 보관 방식 |
| --- | --- | --- | --- |
| 촬영 사진 | AI 그림 생성 | Google Gemini | 브라우저 임시 저장 후 세션 종료 시 삭제 |
| 입력 문장과 선택 항목 | AI 그림 생성 | Google Gemini | 브라우저 세션 동안만 저장 |
| 완성 이미지 | 인쇄 백업 및 문자 링크 | Firebase Storage | 최대 7일 |
| 휴대폰 번호 | 사진 링크 문자 발송 | Solapi | 앱 DB에는 저장하지 않음. Solapi 계정의 로그 정책은 별도 적용 |

## 참가자 안내

1. 첫 화면에서 촬영 사진과 입력 문장이 Google Gemini로 전송될 수 있음을 안내하고 확인을 받습니다.
2. 인쇄 또는 문자 전송 전 Firebase 저장 기간과 Solapi 전달 사실을 다시 안내하고 동의를 받습니다.
3. 미성년 참가자는 보호자 또는 행사 담당 교사의 안내 아래 이용하도록 운영합니다.
4. 참가자가 클라우드 저장을 원하지 않으면 로컬 다운로드만 이용할 수 있습니다.

## 보관 및 삭제

- 앱의 IndexedDB에 저장된 촬영·생성 이미지는 2분간 입력이 없거나 인쇄 흐름이 끝나면 삭제됩니다.
- Firebase Storage의 `prints/YYYY-MM-DD/` 경로에 저장된 완성 이미지는 7일 수명 주기 정책으로 자동 삭제합니다.
- Firebase의 `storage.rules`는 파일 형식과 크기를 제한하지만 보관 기간을 집행하지 않습니다. `storage-lifecycle.json`을 실제 버킷에 별도로 적용해야 합니다.
- 참가자가 조기 삭제를 요청할 경우 담당자는 Firebase Console에서 해당 날짜와 생성 시각의 이미지를 확인해 삭제합니다.

## 운영자 배포 점검표

- `storage.rules`가 배포되어 JPEG 15MB 미만 파일만 생성 가능한지 확인합니다.
- 객체 목록 조회가 차단되고 개별 다운로드 링크만 동작하는지 확인합니다.
- 버킷 수명 주기 정책의 삭제 조건이 7일로 표시되는지 확인합니다.
- 테스트 이미지를 올려 `deleteAfter` 메타데이터가 기록되는지 확인합니다.
- Solapi Console의 메시지 로그와 번호 보관 기간을 학교 정책에 맞게 설정합니다.
- 행사 종료 후 브라우저 사이트 데이터와 예상보다 오래 남은 Firebase 파일을 점검합니다.
